## Behavior and boundaries

Previously the server recording switch rejected new observations and notes but left separately scheduled cognition free to claim work, call models and publish new inferences. Fourteen baseline regressions failed on integration `88244ca`: paused queues still claimed orientation/consolidation; active tasks could renew, reserve calls and publish through pause or pause/resume; the worker still called proposal and verification providers while paused. The restart case also lacked a captured policy revision. These are public synthetic reproductions, not a new held-out evaluation.

Unstarted orientation and consolidation tasks now stay queued while paused, consuming neither attempts nor model-operation reservations. The first claim binds the current recording revision. An automatic retry or process restart preserves that binding. Snapshot preparation, renewal, operation reservation, completion and historical integration's alternate failure/defer publication path reject paused or stale tasks under the same brain lock used by recording controls. The unlocked claim-availability probe is only an optimization: the locked claim rechecks the policy.

Migration 032 adds a nullable `recording_revision` execution field to `memory_jobs`. It does not modify task inputs, source snapshots or allocation/funding authority. Existing rows start unbound; a never-started task binds the current policy on claim, while previously attempted legacy work defaults to revision zero. This avoids granting an interrupted legacy operation fresh authority after a recording-policy change. The field is written in the existing claim update; policy checks use the already-read brain row. No extra model call or policy-read database query is added. The upgrade regression preserves every pre-existing job field and row-level security, checks repeated migration, and rejects negative revisions.

A model call already dispatched cannot be recalled. Usage settlement and failure bookkeeping remain available while paused, including after a pause/resume cycle. Reservations with uncertain outcomes remain charged according to the existing budget rules. An operation that already holds the publication lock may commit before pause is acknowledged; one acquiring it after pause is rejected. Tests cover both policy changes after provider work and the publication-before-pause lock ordering.

Interrupted tasks report `recording_paused` or `recording_stale` and do not automatically revive after resume. Explicit learning recovery after resume creates a separately authorized task, preserving the old failure and cumulative spending. A repeated acknowledgement of an existing recovery does not create another authorization. Work that never started can begin after resume using already recorded history. Existing-history indexing, embeddings, retrieval, export, erasure and ordinary maintenance are not a global processing shutdown. Separate local conversation/timed controls are not synchronized by this change.
