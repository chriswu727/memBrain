## Implemented behavior and limits

The preceding [real-service diagnostic](backend-recording-controls-2026-11-08.md#next-backend-diagnostic-delayed-writes-after-erasure) accepted a delayed observation with recording revision 0 after whole-scope erasure. Explicit erasure and suppression now advance recording authority under the same PostgreSQL brain lock as deletion. Old host captures, queued observations, versioned notes and claimed learning tasks cannot publish with the previous revision. This is deliberately brain-wide even for selective or empty resolved deletions; another brain and the paused state are unchanged. Completed deletion retries do not revoke new captures twice.

Independent deletion intents persist a minimum recording revision. Replaying deletion after restoring an older database applies at least that floor; committed intent receipts make replay idempotent. A real backup/restore test saves a revision-0 checkpoint, changes policy through revision 6, deletes at revision 7, then restores: old revision-6 input remains rejected and new revision-7 input succeeds. Historical intents cannot reconstruct a revision floor never recorded. Arbitrary database rollback without independent authority is not qualified.

Migration 033 binds durable runtime turns to their original recording revision. Existing turns default to zero rather than borrowing current permission. Input, renewal, recall/review reservations, output and orientation retain this authority. Orientation jobs bind it before claim. Failed pre-delivery work can terminate without blocking a fresh turn. Source/dependency errors retain their diagnostic precedence.

A delivery callback already in flight can settle bounded factual metadata and a content hash with `recording_changed` and `content_withheld`; stale returned text is not appended or used to commit stale state. Confirmed delivery remains a fact. Upgrade the Python runtime and service together for the additional turn field and receipt reason.

Internal note replacement is distinct from user deletion. It suppresses superseded notes and retains tombstones, dependency invalidation and an independent recovery intent without revoking the remaining extraction’s recording authority. The intent stores this distinction inside its integrity-protected document. Public forget requests cannot select this server-only exemption. User deletion still stops an old extractor retry even when its current source survives; a fresh turn obtains new authority and rereads surviving context.

Intentional direct API writes that omit optional capture metadata retain their current-policy contract; refreshing permission on an old task is not an authorized retry. This change does not provide ephemeral durable chat, universal receipt equivalence or immediate erasure of disconnected files, and cannot recall an already dispatched external request. R4 remains failed and C5 invalid/unscored. No new paid or subscription-backed evaluation ran.
