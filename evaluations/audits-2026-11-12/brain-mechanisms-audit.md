# Brain mechanisms audit, 2026-11-12

Scope: the mechanisms beyond storage and ranking — background learning and semantic consolidation, episodes, associations, beliefs, patterns, working state and orientation, feedback and reinforcement, access dynamics (decay), the job system that drives them, and runtime mode (`BrainRuntime`, agent sessions, desktop chat). Branch `integration/maturity-candidate` at `5b7ec232` (runtime `fa88a4b`).

Method: read-only. The audit read the code and evaluation reports cited below and built a static import graph. It ran no test, service, database or model. Every claim is at the level **read** (the cited code was read and does what is described) unless marked otherwise. Assessments in section 5 and the plan in section 6 are **judgement**.

## Summary

- **On the default plugin path, every model-driven brain mechanism is off.** Background consolidation, orientation, episodes, associations, beliefs and patterns are written only by `publish_semantic` (`src/membrain/consolidation.py:538-573`). That function runs only for `consolidate` jobs. Those jobs are queued only when `MEMORY_COGNITION_*` is configured (`src/membrain/service.py:535-546`, `src/membrain/learning.py:799-812`, `src/membrain/config.py:165-172`). The plugin profile is created without a cognition model (`src/membrain/host.py:147-151`). Recall still queries all of these tables on every request and gets nothing back.
- **The only "brain" mechanism that changes what a plugin host is shown is time decay**, and it has never been measured where it would matter. Each captured statement starts at activation 0.5 and decays with a 28-day half-life from `recorded_at`. For the default `explore` intent the decay multiplies its ranking score by a weight that falls from about 0.47 to a floor of 0.15 (`src/membrain/candidates.py:457-472`, `src/membrain/dynamics.py:110-167`, `src/membrain/cognition.py:326-331`). Every benchmark stores its history in a few minutes, so the weight is the same for every message and the benchmarks cannot see the effect. In a real installation, a message a year old ranks at about a third of the weight of one from today.
- **Feedback and strengthening by use do not exist on the plugin path.** Reinforcement needs a runtime turn with a prepared selection, an assistant reply that is exactly one recalled statement, and a following user message such as "yes" or "wrong" (`src/membrain/feedback.py:18-30`, `:130-152`, `:351-387`). Plugin hosts create no runtime turns. Recall is read-only and never records access (`last_recalled_at` is never written).
- **The host-driven consolidation that the main line calls for already exists, and it is measured.** `memory_consolidate` hands the host AI batches of messages and saves the cues it returns (`src/membrain/message_cues.py`, `src/membrain/mcp_server.py:213-262`, `src/membrain/host.py:64-97`). Cues written through the product's batches raised held-out LoCoMo answers from 80.7% to 82.7% (61 questions gained, 38 lost, p = 0.027). The model-driven pipeline was never benchmarked. Its paid diagnostics of 2026-10-24 to 10-26 mostly failed their acceptance criteria.
- **About 16,000 of the package's 43,377 lines serve mechanisms that a plugin user never runs.** They are the cognition pipeline (about 9,400 lines) and runtime mode (about 5,400 lines), plus beliefs, patterns, feedback and episode semantics. They are covered by unit and service tests (36 learning test files, about 9,800 lines). The `desktop setup` command still asks interactively for a "model used for memory learning" (`src/membrain/desktop_cli.py:65-73`), and the README tells desktop users to enter one (`README.md:111-121`). Both conflict with the main line.

## 3. What changes what a host is shown today

**It changes what is shown (plugin path):**

1. **Message cues.** They add the `entity` route to ranking (`src/membrain/candidates.py:366-373`). They are measured (section 4).
2. **Decay.** For every intent except `exact_quote`, `episode`, `timeline` and `cue_recovery` (`src/membrain/candidates.py:465`), each candidate's score is multiplied by `rank_weight`. All captured statements share the same dynamics (`activation 0.5`, `retention_priority 0.5`, `episode_fragment`, `src/membrain/cognition.py:326-331`). The half-life is therefore 14 × (1 + 2 × 0.5) = 28 days. The weight is 0.15 + 0.6375 × 0.5 × 2^(−days/28): about 0.47 for a new message, 0.31 at 28 days, 0.18 at 90 days and 0.15 after a year. The weight is applied before the candidate list is cut (`src/membrain/candidates.py:467-474`). Automatic recall uses `explore` (`src/membrain/host.py:1582-1597`), so decay applies to it. `my_replies` switches to `episode` and escapes decay. Nothing on the plugin path can protect a memory from decay: `user_pinned`, `open_commitment`, `distinctive_event` and a higher `retention_priority` are never set on captured statements (only consolidation sets `retention_priority`, `src/membrain/consolidation.py:364`).
   - The clock is `system_time.recorded_at`, which is always the time of storage (`src/membrain/service.py:496`). It is not when the conversation happened. After an archive restore or an import (Hermes `USER.md`), every message counts as new again.

**It is computed or queried but has no effect for a plugin user:**

- **Beliefs, patterns, associations and episodes.** Their tables stay empty, but every recall runs `load_belief_relations` (`src/membrain/service.py:756-760`), two expansion queries (`src/membrain/candidates.py:398-431`) and `load_patterns` when it finds items (`src/membrain/service.py:814-829`). The memory page and structure map also read them.
- **Working state and orientation observations.** Read on every recall (`src/membrain/service.py:762`, `:783`) and empty.
- **`memory_access_state`.** Read on every recall (`src/membrain/candidates.py:457-463`) and never written: `observe_feedback` runs on every user message (`src/membrain/service.py:577-582`) and returns as soon as `_latest_delivery` finds no runtime turn (`src/membrain/feedback.py:130-152`, `:351-360`). In runtime mode it also needs the assistant's reply to consist of exactly the recalled statement (`_sole_statement`, `src/membrain/feedback.py:74-81`), which an ordinary reply never does. So even in runtime mode reinforcement is close to unreachable.
- **`_invalidate`** updates episodes, associations, patterns, beliefs and feedback contributions on every message edit or deletion (`src/membrain/service.py:388-432`). This is correct behaviour and costs a few statements on empty tables.
- **Job orchestration.** `jobs.py` imports the allocation, funding, window, recovery and phase-monitor modules on the default path. The code that does work in them is gated on `semantic_processor` (`src/membrain/learning.py:801-810`).

Cost: no latency measurement isolates these queries. The audit did not measure them.

## 5. Assessment (judgement)

### Per mechanism

| Mechanism | Verdict | Reason and, if re-driven, the work packet |
| --- | --- | --- |
| Statement capture, embeddings, extract/rebuild/embed queue | **Keep as is** | The storage base. It is rule-based or uses the bundled model, and it is measured |
| Message cues and `memory_consolidate` | **Keep, extend** | The only consolidation that is measured to help. Extensions belong in the same packet (see below) |
| Decay | **Keep the hook, re-tune after measuring** | It is live, unmeasured and biased against old evidence, which is what long-term memory is for. Measure first (step 1). The likely fixes are to decay from `valid_time`/`occurred_time` rather than storage time, to flatten the floor, or to apply decay only between candidates of equal relevance. Decide after the numbers |
| Background semantic consolidation (cognition model) | **Freeze, then remove from the product** | It needs a second AI, it was never benchmarked, its diagnostics failed acceptance, and the measured lesson says notes-like derivations do not improve answers. Its useful outputs (episodes, update links) are re-driven below. Its storage tables and read paths stay, so archives and the re-driven writers can use them |
| Learning orchestration (windows, allocations, funding, reconsideration, recovery, phase monitor, cognitive budgets) | **Freeze, then remove** with the pipeline | It exists to meter memBrain's own model. A host-driven packet is metered by the host |
| Episodes | **Re-drive from the host AI** | Packet: one finished conversation's messages, with ids and dates, after their cues (or in the same `memory_consolidate` batch, which already ends at conversation boundaries, `src/membrain/message_cues.py:174-186`). Result: groups of message ids, each with a short title and date ("Caroline's adoption agency visit, May 2023"), saved as `memory_episodes` with members pointing at the messages' statements. Recall already expands seeds through episode members (`src/membrain/candidates.py:412-431`). Gate it first with a model-free upper bound (step 3) |
| Associations | **Freeze; do not rebuild as query-time spreading** | Query-time spreading was simulated and closed. A host-written link between two messages adds little beyond a shared cue, except for updates, which the next row covers |
| Beliefs | **Re-drive narrowly as update links, later** | Packet: a new message whose cue matches an older message's cue (same person, same category), shown side by side. Result: "updates", "contradicts" or "unrelated", saved as a relation between the two messages. Recall marks the older one as superseded and keeps both. Evidence would be LongMemEval knowledge-update and LoCoMo temporal questions, and a synthetic set of changed facts. The general belief graph over derived claims should not be rebuilt |
| Patterns | **Remove** | No measurement, depends on derived claims, and no user-visible need is documented |
| Working state, open loops, orientation | **Freeze with runtime mode** | The host AI holds its own working context. Open commitments are covered by notes with plan status |
| Feedback and reinforcement | **Freeze the current form** | It cannot fire for a plugin user and almost never fires in runtime mode. If strengthening by use is rebuilt (step 6), it should come from signals the host already gives: explicit `memory_recall` queries and the messages the host quotes back |
| Runtime mode (`BrainRuntime`, `AgentSession`, desktop chat, recall controller, answer reviewer) | **Freeze; the owner decides whether to remove it** | It is the second-AI product the main line rules out. It is the only producer of runtime turns, so feedback, working state and orientation go with it |
| Note extraction (proxy) | **Keep as is, pending an owner decision** | It serves hosts without tools. By default it uses the proxy's own upstream model and key, so it adds no new configuration, but memBrain makes the call itself |

### Mechanisms most likely to improve what a user experiences

1. **Decay that does not bury old evidence.** This is the largest unknown on the default path, and it can be measured without a model. Evidence that it works: on LoCoMo and LongMemEval stored at their real session dates, evidence recall for questions about old sessions does not fall below the no-decay arm, and knowledge-update questions do not get worse.
2. **Consolidation as cues on original memories** (built). Extend it within the same packet: let the host mark a message "superseded by" a later one, and offer assistant replies the user later relied on. Evidence: paired held-out LoCoMo and LongMemEval runs, with the gain in several-evidence and knowledge-update questions and no significant loss in single-evidence ones.
3. **Episodes written by the host.** They address the measured multi-evidence gap: the evidence for one question lies in several sessions and does not look like the question. Evidence: the model-free upper bound first; then held-out several-evidence recall rising from the cue baseline of 45.5% without a single-evidence loss.
4. **Forgetting as demotion of what the host judged empty.** A message the host reviewed and gave no cue (greetings, requests, unit conversions) is already identifiable: its sequence is at or below `reviewed_through_sequence` and it has no cue row (`src/membrain/message_cues.py:164-172`). Ranking such messages lower is forgetting driven by the host, at no extra cost. Evidence: with the cue files already recorded, evidence recall should not fall and the share of the block taken by content-free messages should drop. The risk is evidence turns the host left uncued, and the replay will show how often that happens.
5. **Strengthening by use**, last. It can be measured only on a time-spread benchmark with repeated questions, and it risks a rich-get-richer bias.

## 6. Proposed order of work

Each step can be built and measured on its own. Steps 1 to 4 need no paid model call.

1. **Measure decay on time-spread histories (model-free).** Store LoCoMo and LongMemEval histories at their dataset session dates with the scenario clock (`src/membrain/evaluation_clock.py`, `helpers._scenario_clock`). Run the evidence-recall harnesses in three arms: current decay, decay off (weight 1), and decay from `valid_time` with a higher floor. Report recall by the age of the evidence session. Decide the policy and ship it as a policy version change.
2. **Take the second AI out of the plugin and desktop product surface.** Remove the interactive cognition prompt from `desktop setup` (`src/membrain/desktop_cli.py:65-73`) and its warning (`:189`). Align `README.md`, `README.zh-CN.md` and `architecture/autonomous-runtime.contract.json`, which still names a "cognitive_controller" and says host tool calls are not required. Mark runtime mode and the cognition pipeline as frozen. Change no behaviour for existing configured profiles.
3. **Gate episodes with an upper bound (model-free).** Write each LoCoMo session as one episode over its messages' statements, directly into `memory_episodes`, then run evidence recall. If several-evidence recall does not rise above 45.5% held out without a single-evidence loss, close episodes. If it does, build step 4.
4. **Host-written episodes.** Extend the `memory_consolidate` result with optional episode groups and a title. Save them in the existing tables, and erase them with their messages (already done in `_invalidate`). Replay with the stand-in writer used for cues (paid, needs the owner's approval), then try a real host as in the cue trial.
5. **Host-judged forgetting.** Demote reviewed messages that have no cue in ranking. Measure with the recorded cue replays at no model cost; ship only if recall does not fall.
6. **Update links.** When the cues of a new message match an older one's, add the pair to the consolidation batch with the question "does the new one update the old?" Save the answer as a relation and mark the older message as superseded in the recall block. Measure LongMemEval knowledge-update and LoCoMo temporal questions (paid, owner approval).
7. **Remove the frozen code** after one pinned release with no regression: the learning and semantic modules, patterns, the belief writers, the cognitive budgets and, if the owner agrees, runtime mode. Keep the migrations and the read and restore paths that old archives need. Expect about 14,000 to 16,000 source lines and a large share of the 40-minute test suite to go.
8. **Strengthening by use**, only if step 1 shows age matters. Count the host's explicit `memory_recall` hits on a message, and messages quoted back to the user, as uses. Measure on a time-spread benchmark with repeated questions.

### Open questions for the owner

1. **Runtime mode.** Is `membrain desktop chat`, with `BrainRuntime`, a reply model of memBrain's own and the Python SDK sessions, still a product? The main line rules out a second AI, yet runtime mode is that AI. Is it frozen or removed?
2. **Configured cognition.** For existing installations that configured a cognition model, should background learning keep running after the freeze, or stop at once?
3. **Proxy extraction.** For hosts without tools, is a memBrain-initiated call to the proxy's own upstream model allowed, or only host-written notes?
4. **Forgetting.** Should old memories fade from automatic recall at all? Or should age affect only ties and presentation, with memory never ranked lower just for being old?
5. **Host cost ceiling.** How many extra host calls and tokens per session may consolidation-type packets (cues, episodes, update links) spend? The cue trial measured about 0.02 USD against 0.008 USD for a plain short turn on Claude Code.
6. **Hosts without the tool.** For OpenClaw, AstrBot and the proxy, is consolidation simply absent there?
7. **The contract.** Should `architecture/autonomous-runtime.contract.json` be rewritten for the main line, or kept as a historical target?

## Not determined

- The latency cost of the empty-table queries on each recall. No isolated measurement exists, and this audit ran nothing.
- How many real installations have a cognition model configured, or use desktop chat.
- How large the effect of decay is on real recall. Section 3 gives only the formula's weights.
- Whether the cognition pipeline would beat messages plus cues on a benchmark. It was never run, and the audit does not recommend paying to find out.
- The exact number of test files and migrations that removal would retire. Section 1 and step 7 give estimates.
