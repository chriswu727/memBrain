## Behavior

The earlier [real-service diagnostic](backend-bounded-queue-replay-2026-11-08.md#next-control-plane-diagnostic-unresolved) showed two misleading states: server pause still displayed recording on, and local pause displayed a blanket recording pause while direct clients could write. The memory page now exposes the selected brain's authoritative server recording control. It uses the existing per-brain revision check and preserves the server's ingestion, note, cognitive-learning and durable-turn fences. The separate device-capture panel retains local timed pause. Both causes are displayed; resuming either leaves the other unchanged. Remote service pages expose server controls without claiming local-device access.

The authenticated local status endpoint returns the effective state plus explicit local/server states. Its optional brain selector checks ownership before returning local status. The local POST retains device-only semantics but returns the effective home-brain state, so local resume cannot report on while the server remains paused. The page submits the displayed revision for each mutation. Stale changes reject and refresh without automatically borrowing a newer revision. Late status responses cannot overwrite newer reads; unavailable or malformed state hides mutation controls instead of showing recording on.

Every local pause receives a fresh nonce, including repeated pauses under the same clock. Local compare-and-set, pause/resume and expiry cleanup share the session-state lock. An expired read therefore cannot delete a concurrently replaced pause. Hosts also keep capture paused when a pause file is unreadable, malformed, empty or has an invalid expiry; a missing file still means no pause. Explicit local resume can clear damaged metadata without resuming the server. The page's unavailable-state behavior is not described as proof that data already sent to a host or provider was recalled.

## Limits

The selected brain's server gate, installation-wide device capture and per-person conversation controls have different scopes. Conversation pauses are deliberately not promoted to whole-brain pauses; automatic cross-device synchronization is not implemented. Combined status is a snapshot of separately read stores, not a cross-store transaction. A local mutation can succeed before its final server-state read fails; callers must read the state before another deliberate decision. Legacy local API callers may omit the optional revision and retain unconditional mutation semantics. The page always supplies it.

Disconnected hosts cannot immediately discover remote changes. An already dispatched provider or network operation cannot be recalled. Ephemeral durable turns, receipt normalization across AgentRuntime and delayed-write erasure fencing remain open. This batch does not establish better general recall, personality, emotional behavior or held-out privacy-intent understanding. Historical R4 remains failed and C5 invalid/unscored. No paid or subscription-backed evaluation was run.
