## Behavior

Previously, completing a host turn removed its staged input before delivering its messages. A process exit in between could lose the exchange. Completed turns now append and sync the entire scrubbed user/assistant payload to the bounded local journal before writing the completion marker. Replay retains original source keys, ownership, parent links and recording revision. Retrying after an uncertain server acknowledgement relies on server idempotency. Abandoned-input recovery follows the same persist-before-completion ordering.

Queue admission checks the complete encoded batch against the 64 MiB limit. It admits both messages or refuses the exchange, preserves the unfinished stage when full and reports no successful receipt. Failed or short writes attempt to roll back the append and do not consume completion state. A torn UTF-8 line is isolated from later healthy records. Permanent and recording-policy rejections do not become successful receipts; server pause cleanup still removes affected recording cues. Whole-turn-only hosts can start a new public turn after resume without reviving the rejected old callback.

New message admission holds only the short local session and queue-write locks. It does not wait for the replay lock held during network requests. User erasure holds the session and queue-write locks together while removing pending content and completing affected stages, preventing concurrent admission from crossing local cleanup. The existing replay lock still orders erasure against remote replay. Erasure also revokes manual captures from unfinished and completed turns, preventing later tools from using those cleared turns. A new public turn receives fresh permission. This local revocation does not cancel a request that already passed the capture check; server-wide erasure fencing for delayed uncommitted writes remains separate work.

This is a local journal followed by idempotent server writes, not one distributed transaction. User and assistant observations remain separate server transactions; replay can temporarily expose a partial exchange. A callback never admitted still needs a host retry, and abandoned-input recovery cannot reconstruct an unaccepted assistant reply. Previously queued content retains existing local-pause semantics; server recording revisions are checked on replay. Replay still drains a queue snapshot synchronously in FIFO order; this batch does not bound the latency of draining a large backlog or add per-batch acknowledgement checkpoints. Direct SDK/file mirroring and independent AgentRuntime retain separate contracts. This does not establish arbitrary hardware-corruption safety, semantic memory quality or release readiness.

## Verification and cost

On the final runtime, **238 source tests pass**, zero skips, across the journal, host, recording, turn-isolation, recording-policy and manual-capture suites. The 23 journal regressions include full-queue refusal, UTF-8 byte accounting, short/fsync failures, malformed tails, real PostgreSQL idempotency at five crash points, a subprocess killed with `os._exit(37)`, original-policy rejection, slow replay with concurrent admission and concurrent erasure, and revocation of unfinished/completed manual captures after erasure. The preceding runtime `802550d` also passes **47 C5 harness tests locally**, with no provider calls; these deterministic harness checks are not a new scored C5 evaluation. The diagnostic-only fixture update passes the previously failing scenario locally again.

The extracted wheel passes **110 tests**, zero skips, covering delivery, recording and server-policy fences. Imports resolve to the extracted wheel, and **206 runtime inputs** match source byte-for-byte. Both launcher-pin tests, Ruff and wheel/sdist builds pass. Earlier 272-test and 107-test runs covered intermediate implementations and are retained separately rather than added to the final-runtime count.

A local filesystem callback probe compares the previous integration runtime `f742be1` with runtime `802550d` using a fake transport, four ABBA runs and 80 measured callbacks per variant. Median cost changes from **0.633 to 1.060 ms**; p95 changes from **0.892 to 1.248 ms**. The extra synchronous journal write therefore costs about 0.427 ms at the median on this machine. The later change only revokes captures inside erasure; it does not modify the measured finish callback. This is not a database, model, end-to-end recall or sustained-load benchmark. The separate blocked-replay regression verifies admission can finish while another replay remains waiting on its fake network transport.

## Retained failures and scope

Six baseline regressions failed on the preceding implementation. Intermediate runs also exposed a corrupt-metadata digest failure, whole-turn resume incompatibility, and a test fixture that dropped timeline role query parameters. The fixture was corrected to inspect actual stored user and assistant observations without weakening count or identity assertions. The slow-replay regression then failed against the first candidate because admission acquired the replay lock. [Verify 42555311152](https://github.com/chriswu727/memBrain/actions/runs/42555311152) was cancelled for that demonstrated regression; it is not a pass. Runtime `802550d` removes that contention and passes the regression.

[Verify 42555805708](https://github.com/chriswu727/memBrain/actions/runs/42555805708) failed its initial deterministic scenario: after a successful mood reset, the relationship-reset sequence could not obtain a ready service client. **One test failed in 14.49 seconds**; full Python, TypeScript and package-build steps were not reached. The service had already started and stored records. This run did not capture its service lifecycle log, so the original cause remains unconfirmed. The native-loader diagnostic separately reported an unpacked supplier binary missing `libxml2.so.2`; that is not evidence that the already-running managed service failed for the same reason. The same 47-test harness suite passed locally. A follow-up adds captured lifecycle logs without retries or weaker assertions; [Verify 42556484552](https://github.com/chriswu727/memBrain/actions/runs/42556484552) passed that diagnostic but was cancelled after two new regressions demonstrated stale manual captures could still save a note after erasure. The final repair revokes those captures and passes both cases, including fresh-turn recording afterward. [Verify 42556921318](https://github.com/chriswu727/memBrain/actions/runs/42556921318) passes on the final pinned source: **8,130 Python tests in 2,545.72 seconds**, **56 TypeScript tests**, zero test skips, strict types, Ruff and wheel/sdist builds. Three existing multiprocessing fork warnings remain. This later pass does not establish the cause of the earlier readiness failure.

No paid or subscription-backed evaluation ran. Native five-platform qualification and the end-to-end recall benchmark were not repeated; earlier results retain their original runtime scope. Historical R4 remains failed and C5 invalid/unscored. Module 1 still needs local/server control synchronization, ephemeral durable turns and receipt normalization with independent AgentRuntime.
