# Live extraction sources and client cache isolation

Runtime `6c4734949b8398315579e59327f5d20cd8a5400e` replaces cached previous-exchange text with exact source references. The baseline public extraction test exposed a deleted allergy being sent again to the next extraction request; its old assertion explicitly expected that stale text. Reversing the assertion failed before the repair. Two separate real-client tests also failed before the cache repair: the process-wide ensured-brain cache treated separate authenticated installations as one because `MemoryClient` has no `base_url` attribute.

Each queued extraction now resolves current and previous exact revisions through an authenticated, brain-scoped endpoint. Every retry refreshes both messages and current notes. Missing current sources stop extraction; incomplete previous context is omitted. A guarded note transaction checks all exact sources and the dependency generation before creating or replacing records. Previous context is linked as note provenance, so erasing that context invalidates derived notes. Feelings retain current-turn sources separately, allowing a genuinely new feeling after Clear Feelings without treating older context as its origin. Ordinary host notes still support pending references and preserve existing idempotency fingerprints. Ensured-brain state is now local to each client.

These guards do not retract an already dispatched provider request, validate arbitrary model claims semantically, or establish human-like emotion. They prevent stale reuse on later attempts and stale persistence after source changes. No provider or subscription evaluation was run.
