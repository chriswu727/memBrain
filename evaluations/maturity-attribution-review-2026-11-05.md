# Acceptance attribution validation

The gate previously trusted each attributor's top-level `cause` without checking the required `per_type` evidence. Two answers saying `host` could therefore exempt a standing memory error even when their per-type answers said `memory`, or their evidence was absent. A synthetic reproduction produced a false passing R4 gate for both cases. This is an evaluation-tooling defect, not evidence that the memory runtime passed its behavioral gates.

The gate now requires exactly the standing types, a valid cause and nonblank evidence for every type, and an overall cause consistent with those entries. Invalid or inconsistent answers conservatively count as memory-caused. Eight regression cases covering R4 and C5 failed before the correction. Complete, consistent host attribution remains accepted; complete memory attribution remains a failure. Existing disagreement, boundary/deletion and case-identity checks retain their meaning with complete attribution fixtures. No historical scores or source evidence were rewritten.

A bounded independent Claude CLI review completed using only an isolated session with Read/Grep/Glob, disabled hooks, no browser or MCP access, and no Claude Desktop access. Its initial read phase exhausted its turn limit; a one-turn, tool-free continuation summarized the material already read. It did not inspect the synthetic test files or the attribution instructions. It reported no false-pass route in its read scope, but that does not establish correctness: Codex independently reproduced the attribution defect above. This review is not a full independent sign-off.

The reviewer also identified that a null reply crashed the validity command instead of producing its structured invalid result. Codex reproduced four malformed reply crashes, with the two empty-string controls passing, then changed validity to report non-string replies as invalid without exposing reply contents. Manifest-less historical scoring and first-review rubric selection remain procedural limitations: live acceptance must use the frozen manifest and the appropriate review instructions. No held-out scenarios or real-model answers were authored, read or scored in this batch.

The final pipeline, hardening and attempt-driver group passes **365 tests in 13.80 seconds**. Ruff and whitespace checks pass.
