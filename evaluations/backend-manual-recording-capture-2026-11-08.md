## Behavior and boundaries

Manual notes previously checked current recording permission, allowing a delayed tool call to acquire new authority after pause/resume. Lifecycle-integrated tools now require the capture issued when their original public input was staged. The capture binds the session, turn, owner, service target and original server recording revision. Local pause revokes affected captures, including completed-turn captures and the owner's roleplay scopes. New public turns after resume receive new captures. Restart does not refresh old permission, and removed or legacy markers fail closed. Existing 256-finished-turn and 14-day inactive-session bounds still apply.

The plugin, Hermes, ChatMemory, AstrBot and OpenClaw note paths use a common capture validator. Lifecycle-integrated MCP checks both manual notes and observations. Group recording exclusions also apply to ChatMemory's manual notes. The plugin's MCP launcher explicitly enables capture requirements; standalone tools-only MCP retains explicit writes and advertises `recording_capture_required: false`. A supplied capture is checked even in tools-only local mode, and remote MCP without local lifecycle state rejects a supplied capture rather than silently ignoring it. The zero-provider C5 stub copies its actual current-turn capture for compatibility; no paid evaluation or grading criteria changed.

Capture issuance occurs inside the same session lock as input staging. A deterministic interleaving exposed an initial implementation race: a completed implicit turn could be replaced by an identical new input before a second capture lookup, allowing the old caller to borrow the new nonce. Returning the originally issued capture directly removes that race and the extra file lookup. Server note publication still uses the existing recording revision fence. No migration, extra provider call or policy HTTP request is added. These are permission and correctness changes, not new end-to-end recall benchmarks.

A local-only pause cannot recall a request already dispatched after its local check; server recording changes use the existing transactional publication fence. Captures constrain operation lifetime, not semantic truth, and cannot prevent an authorized caller from intentionally substituting a newer token. Direct API/SDK calls, tools-only clients and Hermes file mirroring retain separate contracts. Same-turn local resume does not mint fresh manual-note authority. This does not complete module 1: local/server control synchronization, ephemeral durable turns and crash-atomic delivery remain open.
